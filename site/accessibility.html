Accessibility Statement

Because (app.philmaps.com) · Assessed October 6, 2026

In short: Because conforms to the Web Content Accessibility Guidelines (WCAG) 2.2 at Level AA, and therefore also to WCAG 2.1 and 2.0 at Level AA. The one part not covered is Google's own file picker for Google Drive, which Google provides. Every function can be carried out with the keyboard alone and without dragging, the argument map is presented to screen readers as a structured tree, and an automated accessibility test suite must pass before any version is published. For help, or to report a problem, write to info@disagreewisely.org.

Conformance status

WCAG defines three levels of conformance, A, AA and AAA. Level AA is the level required by the regulations listed below. Because conforms to WCAG 2.2 at Level AA: each of the 55 success criteria at Levels A and AA is either met or does not apply to it. The conformance report gives the result and the basis for it for every criterion. Two matters bear on how that claim should be read.

High-contrast map colors

By default, Because draws argument maps in the colors of the MindMup argument-mapping themes, so that course materials prepared in MindMup look as their authors made them. Several of those colors fall below the WCAG contrast minimums. The white claim numbers on light blue, for example, have a contrast ratio of 2.19:1 against a required 4.5:1. View > High-contrast map colors replaces these colors with ones that meet the minimums: the claim numbers become 5.86:1, the green and red connector labels 5.32:1 and 6.48:1, and the selection border 5.86:1. It also lightens any background color an author has given a claim until the claim's text reaches 4.5:1. WCAG allows a page to conform by offering a presentation that meets a criterion through a control that itself conforms (W3C technique G174), and conformance to criteria 1.4.3 and 1.4.11 relies on this setting. The setting is remembered in the browser, is kept when a map is printed, and never changes the map file. The argument-map figures on this site have no such setting, so they use the high-contrast colors throughout.

Third-party content

Because can open files from Google Drive through Google's own file picker, which appears inside the editor. Signing in to Google Drive or Microsoft OneDrive takes place on Google's and Microsoft's own pages. These are outside our control and were not evaluated. In WCAG's terms this is a statement of partial conformance due to third-party content: the editor would conform fully if the Google Drive picker were removed. The OneDrive file browser is part of Because and is covered by this statement. The cloud integrations are optional, and maps can always be opened and saved as local files through the browser's own file dialogs (File > Open and File > Save).

Scope

This statement covers:

  • the editor at https://app.philmaps.com/app/, in each of its layouts (left-side controls, floating controls, classic top controls, and the arrangement used on screens narrower than 720 pixels), in light and dark mode, with and without high-contrast map colors;
  • the pages at https://app.philmaps.com: the home page, the privacy policy, the terms of service, and this statement.

It does not cover Google's and Microsoft's sign-in pages, the Google Drive file picker, external websites linked from Because, or the content of maps that users write. The text of a map and any colors its author chooses are the author's own content, although the high-contrast setting adjusts those colors for display as described above.

Relation to legal requirements

Because every Level A and AA success criterion of WCAG 2.0 and 2.1 is also a criterion of WCAG 2.2, conformance to WCAG 2.2 Level AA entails conformance to WCAG 2.1 and 2.0 at Level AA. The one exception is criterion 4.1.1 (Parsing), which WCAG 2.2 removed; the W3C has published errata to WCAG 2.0 and 2.1 under which 4.1.1 is always satisfied for content written in HTML.

Accessibility features

  • Keyboard. Every command is in the menus, and frequent ones have keys. The arrow keys move through the map, Escape leaves the map for the menus, and ? opens a list of every key (also under Help > Keyboard shortcuts). Single-character keys act only while the map has focus, so typing elsewhere never changes the map.
  • No dragging required. Edit > Move… (M) attaches the selected claim, reason or objection to another claim, chosen by click or by the arrow keys and Enter, or places it wherever blank canvas is clicked. Move left and Move right reorder claims, Wider claim and Narrower claim resize them, and Detach from the tree sets a claim apart.
  • Screen readers. The map is a tree in which each claim and bracket has its depth in the argument and appears in argument order, so a screen reader can tell which claim each reason or objection answers. Implicit claims, claims marked true or false, notes and connector labels are read with the claim. Changes in save status are announced, and dialogs behave as modal dialogs.
  • Vision. High-contrast map colors and a dark mode are in the View menu. Reasons, objections and neutral connectors are distinguished by the shape of their brackets (rounded, square, and flat) as well as by color. The editor and the pages can be zoomed to 400 percent: at the equivalent width of 320 CSS pixels they reflow without horizontal scrolling. They also accept increased letter, word and line spacing.
  • Motion. When the operating system asks for reduced motion, animations are turned off.

Browsers and assistive technology

Automated testing covers Safari's engine and Chrome; Microsoft Edge uses Chrome's engine. Firefox is expected to work but is not part of the automated suite. With assistive technology, Because has been used with NVDA and Chrome on Windows, and the two problems an NVDA user reported (connector labels that were not read, and no keyboard route out of the map) were corrected in August 2026. Structured testing with JAWS, VoiceOver, Narrator, TalkBack or speech-input software has not yet been carried out.

Known limitations

  • The default map colors are those of the MindMup themes, some of which are below the contrast minimums. Use View > High-contrast map colors.
  • The lines connecting claims are thin targets for a pointer. The same actions are in the Argument menu (Edit connector label, Stronger connector, Weaker connector), and L edits a connector's label.
  • Toolbar hints are the browser's own tooltips, which appear on hover but not on keyboard focus. The same text is each button's accessible name, so screen readers announce it on focus.
  • When a claim is marked true or false, the mark partly covers the claim's number badge. The number remains part of the claim's name for screen readers.
  • The editor cannot yet record that a claim is written in a language other than English, so a screen reader reads every claim with English pronunciation.

Feedback and requests for assistance

If something in Because is difficult or impossible to use with the technology you rely on, or if you need the content of a map in another form, write to info@disagreewisely.org. It helps to include the browser, the operating system, any assistive technology, and what you were trying to do. Accessibility problems are handled as defects: once a problem has been reproduced, it is corrected and a test is added to the project's automated test suite, so that a later version cannot reintroduce it.
